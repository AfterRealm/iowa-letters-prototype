Add a Letter

This form writes a new letter directly to the Omeka S backend. Once Omeka accepts it, the map view picks it up on its next short-poll and the new pin appears with a brief animation. You are the author of the entry — your contribution joins the existing six letters as part of the prototype's live data.

Why this exists

The GIS Developer/Specialist role at LIT names supporting digital mapping projects from inception through completion, including workflow optimization as a core responsibility. This authoring form is the small piece of that loop you can use right now: a Research Manager partnering with the Studio on a faculty-led project shouldn't have to learn the Omeka admin to add a record to a public map. They should be able to fill in a form. Here is that form. Full pipeline notes on the Authoring Pipeline page.

Passphrase required

The passphrase is in the cover letter that pointed you here. It is a soft gate — meant to keep casual visitors out, not to be a real authentication boundary. In production, this form would sit behind University of Iowa institutional SSO.

What happens when you submit

  1. The form payload is shaped into a Dublin Core item record with the same field structure the existing six letters use (title, creator, date, type, language, spatial, description, rights, source).
  2. The payload is POSTed to the Omeka S REST API as the iowa-letters-author user — a role-bounded account whose only permission is to create new items.
  3. Omeka writes the record to its MariaDB instance and returns the new item id.
  4. The map view polls Omeka every ten to fifteen seconds. On the next poll your letter appears with a brief flash and zoom-to animation.
  5. You can verify by opening the map in a separate tab before submitting; you'll see the pin land in real time.

Full details on the authoring pipeline, the role-bounded Omeka user model, and the production-vs-prototype security tradeoffs are on the Authoring Pipeline methodology page.
